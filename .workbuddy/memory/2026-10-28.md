### 关键设计决定：不用 `audio.loop`

原生 `loop` 属性**不会触发 `ended`**，而文章页的「听够 90% 自动标记完成」完全依赖
`ended: true` 的那条 `dailylingo:listen` 上报 —— 一旦改用原生循环，自动完成会卡在最后一帧。
所以必须在 `ended` 里手动 `currentTime = 0` + `play()`，并且**上报要排在判断循环之前**。
validate 用 `re.search(r"audio\.loop\s*=", player_src) is None` 把这条锁住。

- `validate.py`：**PASS 3356 / FAIL 0 / WARN 0**（3352 → +4）
- `pytest -q`：**546 passed**（537 → +9：player_dom +4、progress_dom +2、frontend +3）
- 链接：76 个 HTML 1056 条 / md 225 条，0 坏链；四个资源指纹全站统一
- 耗时：冷 4.77 s / 热 0.38 s / `watch.py --once` 5455 ms
- 文章页 diff 只有 4 行（3 个 JS + 1 个 CSS 的指纹），共 75×4 = 300 行增删

### 仍未验证

本机没有可用浏览器（`msedge --version` 假成功），**真实播放器里循环的听感没听过**：
`ended` 后 seek 到 0 再 `play()` 在 Chrome/iOS Safari 上的实际行为只靠 jsdom 替身推断，
替身里 `ended` 是手写属性，不会像真实浏览器那样在 seek 后自动清掉。
下次有浏览器时值得确认一次：循环第二轮的句子高亮是否从第一句重新开始。
